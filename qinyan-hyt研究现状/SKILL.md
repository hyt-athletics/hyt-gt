# 沁言学术 - 研究现状综述提纲

## 概述

本技能通过沁言学术 OpenAPI 从多个权威学术数据库检索真实文献，围绕用户指定的研究主题进行研究现状梳理，生成结构化的综述提纲、核心观点摘要与研究现状地图。适用于硕士/博士研究生在开题报告准备、论文综述搭建、陌生领域快速入门等场景。

**学术诚信声明：**

- 本技能引用的论文题目、作者、年份、期刊、会议、DOI、URL 等信息必须来自沁言学术 OpenAPI 实际返回结果，严禁捏造文献。
- 当检索结果不足、主题过于冷门、数据源覆盖有限或证据不充分时，应明确说明局限性，不得用常识臆测补齐文献依据。
- 本技能的目标是生成"证据驱动的研究现状提纲"，不是代替用户直接撰写完整论文正文。
- 所有"研究不足""未来方向""研究空白"等判断，只有在检索结果中有明确依据时才可输出，并尽量附带对应文献证据。

## 前置条件

使用前请确保：

1. 已设置 `QINYAN_API_KEY` 环境变量（前往 https://platform.qinyanai.com/ 申请）
2. 环境中可用 `curl` 和 `python3`

```bash

```

## 工作流程

### 第一步：需求诊断与补齐

先解析用户输入，优先提取以下核心信息：

- 研究主题
- 时间范围（若用户未说明，可默认近 3-5 年，但应优先询问确认）
- 学科或应用场景
- 文献语言范围（中文 / 英文 / 中英双语）
- 输出用途（开题报告、论文综述、快速入门、组会汇报等）
- 侧重方向（可选，如算法改进、应用效果、临床价值、教育实践、政策分析等）

执行规则：

- **IF 用户输入信息不足**（例如仅说"帮我写个综述"），则礼貌追问缺失信息，优先补齐"研究主题""时间范围""学科/领域"三个关键项，再决定是否继续追问其他条件。
- **IF 用户输入信息已较完整**（例如"帮我梳理近三年大模型在医疗影像中的研究现状，英文文献优先，用于开题报告"），则不机械重复提问，应简要复述理解结果后直接进入检索。
- **禁止**在主题不明确时自行脑补研究对象并开始检索。

### 第二步：制定检索策略（1+1 黄金组合）

根据主题所属学科和用户需求，选择"一个主数据库 + 一个补充数据库"的组合，将原始检索量控制在约 40-60 篇，再筛选出 20-30 篇高相关文献进入归纳阶段。

**智能选库策略：**

| 学科类型 | 优先源（主库） | 补充源 | 原始总量建议 |
|----------|--------------|--------|------------|
| 医学 / 生物 / 公共卫生 | PubMed（建议 40） | Google Scholar（建议 10） | ~50 篇 |
| 计算机 / 人工智能 / 数理工 | ArXiv（建议 40） | Google Scholar（建议 10） | ~50 篇 |
| 中文社科 / 教育 / 管理 / 政策 | 万方（建议 40） | Google Scholar（建议 10） | ~50 篇 |
| 通用 / 跨学科复合 | Google Scholar（建议 20） | 按重点择一补充（建议 20） | ~40 篇 |

执行原则：

- PubMed 和 ArXiv 不支持中文检索，若用户输入为中文主题，应先转换为规范英文术语再检索。
- 若用户强调"研究现状"或"文献综述"，可优先关注综述型论文，同时保留一定比例的代表性原始研究。
- 若用户指定中文文献优先，则万方优先；若指定英文文献优先，则 Google Scholar、PubMed、ArXiv 优先。
- 不要无差别同时拉满四个数据库，避免文献噪声过多和后续归纳失焦。
- 若用户明确指定数据库或主题具有明显跨学科特征，可在说明理由后适当调整组合。

### 第三步：检索文献

使用 `scripts/search.sh` 检索文献：

```bash
bash scripts/search.sh <source> '<json_payload>'
# source: google | wanfang | pubmed | arxiv
```

**各数据库参数：**

| 数据源 | 命令 | 核心参数 | 说明 |
|--------|------|----------|------|
| Google Scholar | `bash scripts/search.sh google '<json>'` | query, max_results(≤20), date_from, date_to, author | 综合学术 |
| 万方 | `bash scripts/search.sh wanfang '<json>'` | query, max_results(≤100), date_from, date_to | 中文文献 |
| PubMed | `bash scripts/search.sh pubmed '<json>'` | query(英文), max_results(≤200), date_from, date_to | 医学生物 |
| ArXiv | `bash scripts/search.sh arxiv '<json>'` | query(英文), max_results(≤100), date_from, date_to, author | 理工计算机 |

**注意：PubMed 和 ArXiv 不支持中文检索，需将查询词翻译为英文。**

**示例（医学主题，PubMed + Google Scholar 组合）：**

```bash
# 主库：PubMed 40 篇
bash scripts/search.sh pubmed '{"query": "multimodal large language model medical imaging diagnosis", "max_results": 40, "date_from": "2022"}'
# 补充：Google Scholar 10 篇
bash scripts/search.sh google '{"query": "multimodal large language model medical imaging diagnosis", "max_results": 10, "date_from": "2022"}'
```

**示例（AI 主题，ArXiv + Google Scholar 组合）：**

```bash
# 主库：ArXiv 40 篇
bash scripts/search.sh arxiv '{"query": "graph neural network drug discovery", "max_results": 40, "date_from": "2022"}'
# 补充：Google Scholar 10 篇
bash scripts/search.sh google '{"query": "graph neural network drug discovery", "max_results": 10, "date_from": "2022"}'
```

**示例（中文社科主题，万方 + Google Scholar 组合）：**

```bash
# 主库：万方 40 篇
bash scripts/search.sh wanfang '{"query": "人工智能 高等教育 教学改革", "max_results": 40, "date_from": "2022"}'
# 补充：Google Scholar 10 篇
bash scripts/search.sh google '{"query": "artificial intelligence higher education teaching reform", "max_results": 10, "date_from": "2022"}'
```

若任一数据库返回错误或空结果，应在输出中如实说明，不得伪造数据。

### 第四步：去重、相关性筛选与内部评分

对多数据源返回结果进行统一整理，并从中筛选出最适合用于研究现状归纳的高相关文献。

**去重规则（三级漏斗）：**

1. **第一级：DOI 绝对去重** — 只要 DOI 一致，直接判定为同一篇文献，保留信息更完整的一条。
2. **第二级：强特征去重** — 若 DOI 缺失，则结合"标题核心词 + 第一作者 + 发表年份"进行重复判断；允许大小写、标点与轻微表述差异。
3. **第三级：跨语种辅助判断** — 若万方等数据库出现英文原文的中文译介、双语版本或同一团队中英文对应成果，且"年份相同 + 作者对应 + 标题语义高度一致"，可判定为同一项研究，优先保留英文版或元数据更完整的一版。

**相关性筛选规则（三把硬尺子）：**

1. **时间红线** — 文献发表年份超出用户指定或默认时间范围时，直接剔除。
2. **核心概念缺失** — 若标题与摘要中完全不包含用户主题的核心关键词、同义词或常见英文术语，则判定为无关噪声，直接剔除。
3. **学科语境不符** — 若文献使用相同术语但明显属于其他学科语境（如用户研究医学影像，结果却是电网 Transformer），则直接剔除。

**代表性保留规则：**

- 在通过筛选的高相关文献中，兼顾最新研究、经典奠基工作和不同子方向代表作。
- 最终进入归纳阶段的文献建议控制在 20-30 篇左右。
- 若高质量结果不足，应如实说明，不强行凑数。

### 第五步：按研究子主题归类，并在子主题内部梳理演进

基于筛选后的文献，优先按"研究子主题 / 子方向 / 流派"进行分类，再在每个子主题内部补充时间演进、方法变化或问题转移。

执行规则：

- 优先识别 2-5 个主要子主题，不宜过多。
- 每个子主题应回答三个问题：
  1. 这个方向主要解决什么问题？
  2. 当前常见的方法、模型或研究路径是什么？
  3. 近几年这个方向发生了哪些明显变化？
- 时间演进应嵌入各子主题内部，不单独写成空泛章节。
- 若某类文献证据不足以支持单独成类，则不要强行归类。
- 若不同数据库结论存在明显差异，可适当指出，但必须基于实际检索结果。

### 第六步：生成证据驱动的综述提纲与研究现状地图

根据归类结果生成最终输出，重点是"提纲化、证据化、结构化"。

执行规则：

- 输出必须包含"数据漏斗""研究现状全景地图""核心提纲与证据展开"三层结构。
- 每个核心观点后尽量附上真实文献证据，使用 `([作者, 年份])` 或 `[作者, 年份]` 形式标注。
- 每个子主题下应列出 2-5 篇关键支撑文献，供用户继续追溯阅读。
- "研究空白 / 未来展望"部分只有在文献摘要、结论或 future work 中有明确依据时才可提取，不得凭常识自行发挥。
- 参考文献列表优先按 APA 7th 风格整理；若原始字段不足以完整生成 APA 条目，应尽可能规范呈现已有信息，不得补造缺失字段。
- 输出应强调"研究现状提纲"，不要扩写成冗长论文正文。

## 质量要求

1. 所有文献信息必须来自实际检索结果，不得捏造。
2. 输出必须体现"提纲 + 证据 + 地图"三层结构，不能退化为普通摘要。
3. 分类应以研究子主题为主，避免混用过多维度导致结构混乱。
4. 每个核心观点尽量绑定真实文献依据，避免空泛总结。
5. 检索后必须进行去重与相关性筛选，不得将原始结果直接堆砌输出。
6. 对于"研究不足""未来方向""研究空白"的表述必须严格克制，仅在有明确文献证据时输出。
7. 当证据不足、结果较少或主题边界不清时，应明确提示局限性。
8. 语气要求：与用户交互时自然清晰；正式输出时学术、克制、结构严谨。

## 示例工作流

**用户**：帮我梳理一下"多模态大模型在医学影像诊断中的研究现状"，重点看近三年，英文文献优先，我想拿来写开题报告。

**步骤 1：需求诊断与补齐**

- 已识别主题：多模态大模型在医学影像诊断中的研究现状
- 已识别时间范围：近三年（2022-2025）
- 已识别语言偏好：英文优先
- 已识别用途：开题报告
- 学科属性：医学影像 + 人工智能
- 信息已足够，无需追问

**步骤 2：制定检索策略**

- 医学主题 → 优先 PubMed，补充 Google Scholar
- 英文检索词：multimodal large language model medical imaging diagnosis
- 检索计划：PubMed 40 篇 + Google Scholar 10 篇

**步骤 3：多源检索**

```bash
bash scripts/search.sh pubmed '{"query": "multimodal large language model medical imaging diagnosis", "max_results": 40, "date_from": "2022"}'
bash scripts/search.sh google '{"query": "multimodal large language model medical imaging diagnosis", "max_results": 10, "date_from": "2022"}'
```

**步骤 4：去重与筛选**

- 合并 DOI 相同或标题高度相似的重复条目
- 剔除仅提到"language model"但与医学影像诊断无关的结果
- 保留与"多模态""医学影像""诊断辅助"高度相关的高质量文献

**步骤 5：按子主题归类**

- 子主题 1：影像-文本联合表征学习
- 子主题 2：诊断辅助与自动报告生成
- 子主题 3：临床可解释性与应用落地

**步骤 6：生成最终结果**

- 输出数据漏斗与研究现状全景地图
- 输出结构化综述提纲
- 每个核心观点附上真实文献证据
- 按 APA 风格整理核心参考文献
